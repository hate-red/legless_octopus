# Кредитный кабинет — frontend

Интерфейс согласованного макета v12, перенесённый на Next.js 16.4 / React 19 и подключённый к FastAPI.

## Запуск

Из корня репозитория: `docker compose up --build -d`. Открыть http://localhost:3000.

Для разработки отдельно от контейнера frontend:

```powershell
cd frontend
pnpm install --frozen-lockfile
Copy-Item .env.local.example .env.local
pnpm dev
```

Backend должен работать по адресу из `BACKEND_URL` (по умолчанию http://127.0.0.1:8000/api). Если порт 3000 занят: `pnpm dev --port 3100`.

## Стек и структура

- Next.js App Router, TypeScript strict, `src`, Cache Components и Partial Prefetching.
- Zustand: сессия, данные кабинета, этапы заявки, тема и состояние меню.
- React Hook Form + Zod: вход, параметры кредита, компания, решение банка.
- Собственные Button, Input, Field, Modal, Tabs, Alert и состояния загрузки; иконки lucide-react.
- CSS без готовой библиотеки компонентов, светлая и тёмная темы.

Упрощённый FSD: слой `app` объединяет маршрутизацию и композицию страниц.

```text
src/
  app/                 # Маршруты, экраны, провайдеры, стили и серверный BFF
  widgets/app-shell/   # Боковое меню, верхняя панель, навигация
  widgets/loan-wizard/ # Форма заявки: объединяет параметры и документы
  widgets/company-profile/ # Компания: сведения, редактирование, документы
  features/            # auth, loan, company, documents, bank-review
  entities/            # session, cabinet: состояние и представление данных
  shared/              # API-контракты, клиент, форматирование, UI, настройки
```

Зависимости направлены вниз по слоям. Типы HTTP-контрактов хранятся в `shared/api/contracts.ts`; `entities/cabinet/model/types.ts` их переэкспортирует. API компаний, заявок и документов не кешируется между пользователями. Публичный компонент входа использует `use cache`; закрытые страницы читают сессию и данные во время работы приложения и отключают проверку instant-навигации.

## Работа с backend

Браузер обращается к `/api/backend/*`. Route Handler проксирует запросы в FastAPI, проверяет Origin для изменений и хранит JWT в HttpOnly SameSite cookie. JWT не попадает в localStorage. В localStorage сохраняются только тема и состояние меню.

`BACKEND_URL` — серверная переменная; в Docker это `http://backend:8000/api`. `COOKIE_SECURE=true` нужен при HTTPS. За reverse proxy можно задать `APP_ORIGIN`, например `https://cabinet.example.com`.

Работают:

- Вход с email/паролем или ИНН/паролем, демо-вход в реальные seed-аккаунты.
- Первый вход сразу открывает форму. Есть черновик — главная предлагает продолжить; есть результат — показывает скор и условия.
- Автосохранение валидных параметров, ограничения продуктов из API, удаление и восстановление черновика.
- PDF до 10 МБ: загрузка, просмотр, версии и подтверждение актуальности.
- Отправка на серверный скоринг, история, факторы оценки, встречное предложение, согласование и демонстрационное подписание.
- Компания: реквизиты, финансы, контакты, редактирование и документы.
- Уведомления о статусах с сохранением отметок прочтения.
- Банк: очередь, фильтры, данные проверок, просмотр документов, запрос обновления, ответ клиента, одобрение/отказ.

Пароль тестовых аккаунтов `password123`. Аккаунты: `client1@example.com`, `client2@example.com`, `client3@example.com`, `bank@example.com`. Они доступны и через кнопки на экране входа. Самостоятельная регистрация не предусмотрена текущим backend.

Скор и статусы возвращает backend. Внешние проверки реестров и выдача средств остаются демонстрационными возможностями проекта. PDF хранятся в PostgreSQL и не используются как вход для извлечения финансовых показателей.

## Проверки

```powershell
pnpm typecheck
pnpm lint
pnpm build
pnpm format:check
pnpm test:e2e
pnpm smoke
```

Playwright использует установленный Microsoft Edge. `E2E_BASE_URL` по умолчанию http://localhost:3100. Тесты создают заявки и меняют документы: запускайте их с отдельной тестовой базой, а не с пользовательскими данными. Проверяются отправка заявки, восстановление черновика, INN-вход, темы, мобильный экран и полный обмен документами между клиентом и банком. Артефакты сохраняются в `.artifacts` и `test-results` (не входят в Git).

Для браузерной проверки с отдельным API задайте `BACKEND_URL=http://127.0.0.1:8100/api` при запуске dev-сервера. API-проверки описаны в `backend/tests/test_cabinet_api.py`.

`pnpm smoke` проверяет уже запущенный production-интерфейс на http://localhost:3000 без изменения данных: вход, cookie, защиту Origin, просмотр PDF, темы и ширины 320–1280 px. Адрес можно переопределить через `SMOKE_BASE_URL`.
